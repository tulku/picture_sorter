# User-operated migration

The automated build does not migrate personal photos, alter Syncthing/Immich settings or install/start a production service. Perform deployment only after independent review and qualification.

1. Back up the archive and existing edits. Inventory the old layout and current writers. Stop the old importer and exclude/stop Syncthing management of the proposed working/state trees **before** activating the new cache. Confirm no old process can write them. Keep the old sorter available as the explicitly named `photo_sorter_legacy`; never run it concurrently over a managed tree.
2. Choose new disjoint local working/state directories. Keep the existing NAS layout; bootstrap adopts verified originals in place without reorganizing them. Create a new local profile with `init`, inspect every root/identity and budget, then run read-only `doctor`. Do not copy the example identities or another client's writer ID. Keep live SQLite entirely local.
3. Run the service against the reviewed profile. Qualify NAS semantics using a separate explicit scratch directory on the same mount, never an archive photo directory. Obtain distinct-client handoff/disconnect evidence before allowing multiple publishers. Missing qualification keeps production publication disabled. See [compatibility](compatibility.md).
4. Explicitly initialize the archive marker with `archive init` only after confirming its archive identity and target path. Preview `bootstrap --dry-run`, then run `bootstrap` with a reviewed optional archive-relative `--scope`. It journals adopted verified bytes and retains unknown edits/history. Resume waiting jobs with the same operation instead of deleting staging or lock evidence.
5. Preview an isolated camera import, then validate a small real import, `verify`, `verify --archive`, status, pin, offline saved edit capture and foreground `refresh --editor-closed`. Default import success means ingested, not necessarily archived. Confirm the archived milestone before any source-card retention decision.
6. Qualify installed RapidRAW using isolated native saves/reopens/reset and installed Immich using an explicitly selected disposable JPEG. Check exact versions, library/path mappings, private key permissions and report scope. Leave unknown/unrun capabilities disabled. Decide explicitly whether the documented best-effort rating race is acceptable. GIMP projects and native Immich edits do not receive semantic synchronization.
7. Review backup/rebuild and abandoned-lock procedures. Install the generated user service and point the quoted runner at the reviewed explicit profile/card path yourself. Confirm old Syncthing/importer exclusions remain effective. Observe status and budget through a complete offline/reconnect cycle before routine use.

Keep rollback copies of old configuration, archive, local edits and catalog state. Rolling back software does not authorize concurrent writers, deleting causal history or downgrading a newer catalog. Stop/reap all writers and inspect archive mode/history before switching owners. Deployment probes are real operations on explicitly disposable scratch/assets and must be authorized separately from this isolated implementation run.
