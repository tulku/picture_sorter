# Fast SD-card imports

The normal workflow is insert the card and run photo_sorter. Enumerate file metadata, reuse persistent evidence for the same identified source and unchanged originals, copy only new content locally, and return at the ingested milestone. NAS upload remains durable background work; --wait-for archived explicitly waits. Show periodic progress for human imports and retained-job waits. JSON stays one final response.

The NAS catalogue is the source of canonical archived placement: identical originals and fingerprint-equivalent JPEG metadata variants must reuse existing NAS paths even when the current sequence planner would choose a different burst directory. No selection directory is part of the normal user workflow. Ambiguous canonical matches remain reviewable conflicts. Whole-file digests still govern copied bytes. --strict bypasses source shortcuts and retains full verification. Unknown/unidentifiable sources fall back to hashing; companions remain independently inspected.

Use a stable source incarnation (physical filesystem/card identity and source location) plus path, size, and modification fingerprint. Fast mode trusts this metadata; it is not byte verification against silent mutation. The current card already has a completed full scan: add an explicit native source-history adoption operation, validate that this source and every adopted file's metadata match that job, and bind that one-time history to the identified current card. Never implicitly reuse unbound history on a different card.

Reuse verified JPEG fingerprints from the catalogue. Populate missing NAS JPEG fingerprints through a native read-only archive indexing operation and include them in future bootstrap hashing, rather than rereading known JPEG data on every import. This one-time completion of the image index can run while implementation proceeds. Preserve all existing NAS bytes and metadata; publication rules remain unchanged.

Approaches: keep temporary selections (rejected: not a normal workflow); hash every card file every time (rejected: defeats persistent index); persistent source cache plus content-based canonical reuse (chosen: matches the requested workflow). Changes remain in the native importer, with a small configured CLI default change. No timestamp cutoff, automatic card deletion, automatic NAS moves, or metadata replacement.

Acceptance: native repeat import of an unchanged identified card hashes/copies zero old bytes; appending new photos hashes/copies only those photos; card swap or changed metadata invalidates shortcuts; --strict detects same-size/same-time changes; existing flat NAS paths beat newly inferred burst paths; local milestone works with NAS offline and background upload later completes; progress appears before completion, including a waiting reason; normal syl command uses the configured SD root and ingested milestone, with an optional archive wait. Validate against the real catalogue via read-only preview before any real import.
