# Generated editing output sync

The user requests automatic archival of HDR TIFFs and other files generated while editing in Working. Immich setup is explicitly deferred. Two current HDR renders (about242MB each) exist only locally with archived but unassociated saved metadata. Keep their relative HDR folders. No one-time selection directory should be needed for future saves.

Use the existing coherent snapshots, reservations, saved versions, heads, immutable NAS history and projection queue for generated files. Introduce explicit SidecarKind::Generated and GENERATED_OUTPUT_OWNER="generated-output". This is an internal saved-file role, not permission for arbitrary metadata to overwrite media. Keep validate_sidecar_path strict; owner-aware validators accept generated paths only for this role. Registration and journal replay reject known camera members, placements and pending import destinations, including case-equivalent paths. Member attachment must also reject generated claims. Never infer that a modified known camera original is generated.

Generated files get independent groups, without fake OriginalMember placements. Existing camera groups and HDR/burst sequences remain intact. Publication emits GroupCreated before a new generated saved-file identity and permits generated groups/adjacent metadata without requiring archived camera members. Generated groups remain excluded from eviction initially. Readiness accounts for their saved-file state. Existing orphan adjacent metadata is associated by exact full generated filename through native semantic resolution after the generated base has been archived; discovery order must not create permanent orphaning.

Watch close/rename events and startup/periodic inventory. Recognize rendered images and videos, excluding camera RAW formats, plus common opaque editing projects (PSD/XCF/KRA/ORA/EXR/HDR/AFPHOTO). Ignore hidden/internal/system/temp/partial names. Persistent generated_observations(path,stamp,stable_since,captured_stamp,present) debounce new/changed outputs and skip all byte reads for unchanged files across restart. Coherent capture tolerates source changes by retrying; only matching captured source stamps are acknowledged. Preserve observed generations offline under the existing space/reservation constraints. Local absence does not publish a Reset or delete the last NAS save.

Approaches: reusing immutable camera membership is incompatible with later saves; a separate parallel asset/version subsystem duplicates existing reliable machinery. Use the explicit generated saved-file role and existing version machinery. The default visible policy is newest save at the same NAS filename with older versions retained; an optional user preference question remains open, so keep version preservation unconditional.

For generated NAS projections only, implement a recoverable move-and-publish protocol on qualified SingleWriter mounts. Keep the exchange requirement unchanged for ordinary metadata. Require committed projection proof, current archive identity, new immutable history, a matching immutable generated-owner manifest, and qualified generated-replacement evidence. First claim must reject an existing NAS target even if bytes match. Owner claim is recorded while the target is absent, and first publication still expects absence, so a concurrent foreign arrival causes conflict rather than adoption. Native catalog/replay ownership checks remain authoritative for journaled originals whose file is absent.

Prepare and verify new staged bytes before moving the old file. Move old visible bytes with no-replace into deterministic retained storage, verify the displaced content against expected, then publish new bytes with no-replace. Never delete retained unknown bytes. Recovery handles old-live, absent-live plus retained-old, new-live plus retained-old, foreign-live, existing retained target and lost replies. Manifest/retained checks precede AlreadyCurrent. Unexpected displaced bytes are retained and stop publication. Temporary absence between the two moves is an explicit availability tradeoff; recovery must finish from durable intent/history. Do not enable replacement until protocol fault tests and a real scratch deployment probe succeed. Do not bump the existing base NAS implementation fingerprint or invalidate existing import qualification.

No app activation by the agent: build/test, merge/push source main and pin/build/commit Nix as already authorized; user switches syl. The new service then discovers and archives the current two TIFFs automatically. Preserve eskarina configuration for later activation, but do not use that host today.
